## Open edX AI Extensibility Framework

<https://docs.openedx.org/projects/openedx-ai-extensions/>

<!-- Note -->
The *Open edX AI Extensibility Framework* (formerly the *Open edX AI Extensions*, but apparently that wasn't enough of a mouthful, or maybe they piped it through an LLM; not sure) is an Open edX community effort to add GenAI capabilities to Open edX.

By "community effort" I mean it's not driven by developers employed by Axim, but rather by another company ([edunext](https://www.edunext.co/) out of Colombia) that has been part of the Open edX community nearly from the beginning.


## How it works <!-- .element class="hidden" -->

... uses the LiteLLM Python SDK

... supports any OpenAI-compatible API

... can also run with local Ollama instances

<!-- Note -->
The configuration required on the Open edX side effectively amounts to 

* telling Open edX the URL of an OpenAI-compatible API endpoint,
* configuring it with an API key, and
* selecting a model if the endpoint supports several.

Background info:

* <https://docs.litellm.ai/#basic-usage>


## Usage examples 

(for learners)

<!-- Note -->
In principle we can prime the LLMs with which we interact with any system prompt we like.
So we can essentially do "anything" with the LLM.

But the framework does come with a few pre-configured usage examples, which we can broadly categorise as learner-facing and author-facing.

We'll start with the learner-facing ones.


## AI summary

<!-- Note -->
The first option is to create an "AI summary" from the existing course content.
This one I consider a bit problematic:

* Just restating the content in different words isn't particularly helpful nor conducive to learning.
* Often, unless you're prompting the LLM explicitly to reduce the word count, you end up getting a "summary" that is longer than the original.
* However, if you *do* restrict the output length, you'll often lose content that is quite critical for understanding the material.
* Conversely, you can't prompt the LLM to put the material into a wider context, because you're risking hallucinations.

## Retrieval-Augmented Generation

(RAG)

<!-- Note -->
What this actually is is a concept known as [Retrieval-Augmented Generation](https://en.wikipedia.org/wiki/Retrieval-augmented_generation) or RAG.

What this does is it primes an existing large-language model (LLM) with specific content, and then allows the learner to ask natural-language questions about that content.

This is different from [fine-tuning](https://en.wikipedia.org/wiki/Fine-tuning_(deep_learning)), which is a much more involved and resource-intensive process:
with RAG, you take an existing, unmodified model and feed it some context, and then you use a prompt to specify that it must include that context in the answers it gives.

This gives the learner the ability to interact with the course material via a chatbot.
And this does have merit: it relieves course authors of having to deal with learner questions that arise from simply not having read the material. (This is more common than you'd think.)


## Usage examples 

(for course authors)

<!-- Note -->
So, we have seen a few examples that are ostensibly for the learners' benefit (even though, as we've seen, they benefit course authors as well, perhaps even more).

Now, let's move on to AI assistance specifically for course authors.


## Creating question banks from course content

<!-- Note -->
The AI extensions also give course authors the ability to create a question bank from existing course material.

This is often quite helpful when you've written, say, 5,000 words of course material and you now need a question bank of 50 questions, out of which 5-10 are presented to each learner in a review quiz.

The approach that the Open edX developers take is very much a "human in the loop" one: you don't use the LLM to generate the questions on the fly, and then grade the learner based on that.
Instead, you use the LLM to draft questions for a question bank (a "content library" in Open edX parlance), then the course author reviews and corrects them, and then you use a simple randomiser to allocate questions to each learner's quiz.
